Methodology & limitations

How the score is built

The composite blends volume (commits + churn), consistency (active days & cadence), and quality{% if llm %}, plus model-judged quality (RACE craftsmanship + authenticity){% endif %}. Scores are shrunk for small samples (credibility = commits ÷ (commits + 8)) so a single drive-by commit can't out-rank sustained work.

Deterministic git signals (both modes, no LLM): Diff Risk Score (churn · dispersion · hotspots · alignment), test-touch rate, AI stylometry, and message↔diff alignment. Grounded in the indexed corpus (165 papers): RACE/static-analysis (2508.14419), rubric design (2512.20159), JIT defect prediction (2605.17548, 2605.30208), AI detection (2601.19264), judge reliability (2605.20351).

Limitations — read the scores with these in mind

  • Single-model bias. {% if meta.panel_models %}Mitigated here by a multi-model panel (agreement reported above).{% else %}One model judges quality and AI-likelihood; a model can favor its own style. Enable the judge panel in Settings to mitigate.{% endif %}
  • Gaming. The judge is instructed to weigh the diff over the commit message, and a deterministic message↔diff alignment check flags mismatches — but a determined author can still influence scores.
  • AI detection is a signal, not proof. Stylometry and the LLM guess are heuristics; treat sharp disagreement as low-confidence.
  • Sampling. {% if meta.sampled %}Only {{ meta.judged }} of {{ t.commits|intcomma }} commits were judged; unsampled contributors show "not sampled".{% else %}All commits were judged.{% endif %} Confidence badges reflect per-contributor sample size.
  • Static analysis coverage. Complexity is multi-language (lizard); deep bug/security linting is Python-only (ruff) today.
